# str2str 観測データ補正機能（obscorr）

str2str に、入力 RTCM3 ストリームの観測データ（搬送波位相・コード擬似距離）へ
グリッド定義の補正ファイルに基づく補正を適用し、補正後の RTCM3 ストリームを
再配信する機能を追加しています。

## 機能概要

- 入力 RTCM3 をデコードし、各エポックにおける各衛星の仰角・方位角を計算
- 補正ファイルから「衛星 × 周波数バンド × 仰角方位角グリッドセル」が合致する
  補正値（搬送波位相 [cycle]、コード擬似距離 [m]）を検索
- デコードした観測値から補正値を**減算**（L -= Δφ, P -= Δρ）して再エンコード・配信
- 補正値が見つからない場合や何らかのエラー時は、**無補正のまま配信**（パススルー）
  し、警告ログを出力する。補正機能が原因でストリームが停止することはない
- 補正ファイルは稼働中に定期的に更新チェックされ、変更があれば自動再読み込み

対象衛星系: GPS / GLONASS / Galileo / QZSS / BeiDou

## コマンドラインオプション

```
-corr    file    補正ファイルパス（CSV またはバイナリ、自動判別）
                 指定した場合のみ補正が有効。無指定なら従来どおり
-corrint sec     補正ファイルの再読込チェック間隔 [秒]（デフォルト 30）
-navf    file    RINEX ナビゲーションファイル
                 ストリームに航法メッセージが含まれない場合の
                 仰角・方位角計算用フォールバック
```

使用例:

```sh
./str2str -in ntrip://user:pass@host:2101/MOUNT#rtcm3 \
          -out tcpsvr://:2102#rtcm3 -msg "1077,1087,1097,1117,1127,1019,1020" \
          -p 38.26 140.84 100.0 \
          -corr /data/corr/grid_corr.csv -navf /data/nav/brdc.nav -t 3
```

## 補正ファイル仕様

### CSV 形式（プロトタイプ）

1 行が 1 グリッドセルに対応します。

```
# obscorr v1
# prn,band,el_lo,el_hi,az_lo,az_hi,ph_corr_cyc,pr_corr_m,count
G01,L1,10,15,0,5,0.0123,0.45,1523
R07,L2,10,15,0,5,-0.0051,0.12,987
```

| カラム | 内容 |
|---|---|
| prn | RINEX 衛星 ID（G01, R07, E12, J01, C23 …） |
| band | 周波数バンド `L1` / `L2`（数値 `1` / `2` も可） |
| el_lo, el_hi | 仰角グリッドセルの下限・上限 [deg] |
| az_lo, az_hi | 方位角グリッドセルの下限・上限 [deg] |
| ph_corr_cyc | 搬送波位相補正値 [cycle]（観測値から減算される） |
| pr_corr_m | コード擬似距離補正値 [m]（観測値から減算される） |
| count | グリッド内データ数（品質チェック用に保持。現状は補正可否の判定には未使用） |

- 行頭が `#` または `%` の行はコメント。ヘッダ行（`prn` を含む非データ行）は自動スキップ
- 不正な行は行番号付きの警告ログを出してスキップし、他の行の読み込みは継続
- セル判定は `lo <= 角度 < hi`（最上端セルのみ上限を含む）。方位角は 0–360°に正規化して検索
- グリッドは等間隔でなくてもよい（等間隔の場合は自動判定して O(1) 検索、
  不等間隔の場合は二分探索）
- 同一セルの行が重複した場合はファイル内で後の行が有効
- ファイルに存在しないセル・衛星・バンドは「補正なし」となり、該当観測値は
  無補正で配信＋警告ログ

#### 周波数バンドの対応

補正ファイルの L1/L2 は RTKLIB の周波数インデックス 0/1 に機械的に対応します。

| band | GPS | GLONASS | Galileo | BeiDou | QZSS |
|---|---|---|---|---|---|
| L1 | L1 | G1 | E1 | B1I | L1 |
| L2 | L2 | G2 | E5b | B2I/B2b | L2 |

L5/E5a 等の第 3 周波数以降は補正対象外です（無補正で配信、警告なし）。

### バイナリ形式

先頭 4 バイトのマジック `OCB1` で自動判別されます（マジック不一致なら CSV として
パース）。リトルエンディアン固定。

```
ヘッダ (28 バイト):
  magic   "OCB1"     4 バイト
  version u16        フォーマットバージョン
  endian  u16        0x1234（エンディアン確認用マーカー）
  nrec    u32        レコード数
  reserved           16 バイト

レコード (32 バイト × nrec):
  sys     u8         衛星系文字 ('G','R','E','J','C')
  prn     u8         PRN 番号
  band    u8         1:L1, 2:L2
  pad     u8
  el_lo, el_hi, az_lo, az_hi, ph, pr   f32 × 6
  count   i32
```

## 動作仕様の詳細

### 仰角・方位角の計算

- 衛星位置はブロードキャストエフェメリスから計算（`satposs`）。エフェメリスは
  ストリーム中の航法メッセージ（1019/1020/1041/1042/1044/1045/1046）から自動蓄積
- ストリームに当該衛星のエフェメリスが無い場合のみ、`-navf` で指定した RINEX
  ナビゲーションファイルのデータで再計算（フォールバック方式）
- 受信機位置は `-p`/`-px` オプション指定値を優先し、未指定の場合はストリーム中の
  RTCM 1005/1006 の局位置を使用。どちらも無い場合はそのエポック全体を無補正で
  配信し警告を出力
- 仰角・方位角は衛星ごとにエポックあたり 1 回計算し、同一衛星の全周波数で共用

### 再読み込み

- `-corrint` 秒ごとにファイルの mtime をチェックし、変化があれば再読み込み
- 新テーブルの構築に成功した場合のみ入れ替え。**読込・パース失敗時は旧テーブルを
  維持**して補正を継続（警告ログ出力）
- `-navf` のナビゲーションファイルも同じ仕組みで自動再読み込みされる
- mtime が現在時刻から 2 秒以内の場合は書き込み途中の可能性があるとみなし、
  次のチェック周期まで読み込みを遅延

### エラー処理（すべて無補正パススルー・停止しない）

| 事象 | 動作 | ログレベル |
|---|---|---|
| 起動時に補正ファイルが無い/読めない | 無補正で稼働開始、ファイルが現れたら自動的に補正開始 | trace(2) + stderr |
| 再読込失敗 | 旧テーブル維持で補正継続 | trace(2) |
| 行パースエラー | 当該行スキップ | trace(2) 行番号付き |
| グリッド該当セルなし | 当該衛星・周波数のみ無補正 | trace(3) 衛星,周波数,時刻,仰角,方位角 |
| エフェメリスなし | 当該衛星無補正 | trace(3) |
| 受信機位置未確定 | エポック全体無補正 | trace(3) |

ログは既存の trace 機能（`-t level` / `-fl file`）に出力されます。補正関連の警告を
確認するには `-t 3` 以上を指定してください（`-t 4` で補正適用の詳細も出力）。
同種の警告は 1 分あたり最大 20 件に制限され、超過分は件数サマリで出力されます。

## 使用上の注意

- **補正が有効なのはフォーマット変換経路のみ**です。入力・出力の両方に `#rtcm3`
  等のフォーマット指定を付け、デコード→再エンコードが行われる構成にしてください。
  フォーマット指定なしの単純中継（バイトコピー）では補正されません
- 出力フォーマットは既存 str2str と同様 RTCM3 のみ対応
- 補正は**全出力ストリーム共通**です（出力ごとに異なる補正ファイルは指定不可）
- 受信機位置が必要です。ストリームに RTCM 1005/1006 が含まれない場合は
  `-p lat lon hgt` または `-px x y z` を必ず指定してください
- ストリームに航法メッセージが含まれない場合は `-navf` を指定してください。
  どちらも無い場合、仰角・方位角が計算できず全観測値が無補正になります
- 補正ファイルの更新は `mv` によるアトミックな置き換えを推奨します
  （書き込み途中のファイルを読むことを避けるため）
- 補正値の符号規約は「観測値から減算」です（L -= ph_corr, P -= pr_corr）
- Doppler・SNR・LLI（ロックロスフラグ）は変更しません。補正値がサブサイクル量
  である限り、再エンコード時に位相スリップが誤検出されることはありません。
  ただし補正ファイル更新の瞬間に補正値が不連続に変わるため、下流で RTK 等の
  搬送波位相を連続利用する場合はその影響に留意してください
- グリッド内データ数（count）は読み込み・保持していますが、現状では補正可否の
  閾値判定には使用していません（将来拡張用）

## 実装構成

| ファイル | 内容 |
|---|---|
| `src/obscorr.c` | 新規: 補正ファイル読込・グリッド検索・補正適用・再読込 |
| `src/rtklib.h` | `obscorr_t`/`corrtab_t`/`corrgrid_t` 型定義と API 宣言を追加 |
| `src/streamsvr.c` | `strsvrsetcorr()` 追加、`strconv()` に補正フック、サーバスレッドに再読込フック |
| `app/consapp/str2str/str2str.c` | `-corr`/`-corrint`/`-navf` オプション追加 |
| `app/consapp/str2str/gcc/makefile` | `obscorr.o` `ephemeris.o` `rinex.o` を追加 |

補正処理はストリームサーバスレッド内で観測エポック確定時（デコード後・再エンコード
直前）に同期的に実行されます。処理コストはエポックあたり数十 µs 程度
（衛星位置計算が支配的）で、リアルタイム配信への遅延影響は無視できます。
テーブルの参照と再読み込みは同一スレッド内で行われるため排他制御は不要です。
